## 2. 你可以从哪儿拿到（三条路，按推荐顺序）

### A. 社区镜像仓库（最省事，但不是官方）

有人把发行包留了档，例如 `github.com/XingYunStar/NapCatQQ` 的 Releases 里仍有：

- `NapCat.Shell.zip`（Windows shell 版，最常用）
- `NapCat.Shell.Windows.OneKey.zip`（一键安装包）
- `NapCat.Framework.zip`
- docker 镜像 tar（amd64 / arm64）及各自的 `.sha256`

**这是第三方镜像，不是官方发布。** 用之前先按第 3 节核对校验值。

### B. 社区分流

中文社区（QQ 群、论坛、网盘）一直有人留档。风险同上：来源不明，必须校验。

### C. 源码自行构建

上游仓库还在，可以 clone 下来自己构建。门槛最高（要 Node 环境、要能对上 QQ 版本），
但这是唯一「完全掌握来源」的做法。

> **不要做的事**：不要去下「打包好 QQ 客户端 + NapCat」的整合包。那里面是腾讯的闭源客户端，
> 转发和使用都有版权与协议问题，也不该进任何公开仓库。

## 3. 拿到之后怎么校验

我们实际跑通过的那一套，指纹在 [`napcat/CHECKSUMS.txt`](../napcat/CHECKSUMS.txt)：

```powershell
Get-FileHash .\NapCat.Shell.zip -Algorithm SHA256
# 和 CHECKSUMS.txt 里的值逐字比对，不一致就别用
```

校验值对不上，说明文件被改过或被换过——那就别解压，更别让它去注入 QQ。

## 4. 把 OneBot 接到 AstrBot

1. 装好并启动 NapCat，打开 WebUI（默认 `http://127.0.0.1:6099`）
2. 扫码登录小鲸那个 QQ
3. 在 NapCat 的「网络配置」里加一个 **WebSocket 客户端（反向 WS）**：

   ```
   ws://127.0.0.1:6199/ws
   ```

   AstrBot 侧是 WS 服务端（默认 `6199`），收到连接就显示在线。

4. 需要 HTTP 推送（比如某些插件主动发消息）时，再开一个 HTTP 服务端到 `6180`。

样例见 `napcat/onebot11.example.json`。

## 5. `napcat/` 目录里的「挂件」是什么

这个仓库的 `napcat/` 放的是**与我们这套东西强相关的那部分脚本**（都是我们自己写的）：

- `qq-update-guard.ps1` —— QQ 自动升级会把 NapCat 顶掉线。这个脚本盯住
  `QQNT\versions\config.json`，把 `hotUpdate.ready` 清回 false，让启动器停在当前版本
- `qq-update-guard.vbs` —— 隐藏窗口跑它，配合任务计划

> 原理与风险：脚本只改「ready / pendingVersion」这两个字段，不动安装文件、不碰账号数据，
> 写回时强制 UTF-8 无 BOM（QQ 自己读这个文件，BOM 会让它报配置损坏）。

不用版本锁的话，删掉这两个文件不影响其它功能。

## 6. 风险提示（请读一遍）

- **供应链风险**：NapCat 的工作方式是「注入进 QQ 进程」。来源不明的包可以做到任何事——你等于把机器交给它。
- **版本耦合**：它只适配特定 QQNT 版本，QQ 一升级就可能全挂。这就是 `qq-update-guard.ps1` 存在的原因。
- **法律风险**：上游无许可证 + 内含腾讯客户端，这一层风险由**使用者自己**承担；本仓库不提供、不背书。
- **账号风险**：非官方客户端接入可能触发腾讯风控，建议用小号。

---

## 7. 想彻底避开这条路

如果目标只是「让 AstrBot 接上一个 QQ 账号」，可以考虑仍在维护、许可证明确的 OneBot 实现
（不同实现的上线方式、稳定性、风控表现差别很大，选之前自己核实许可证与维护状态）。
本项目与任何具体实现解耦：只要它能提供 OneBot v11 的反向 WS，第 4 节的接法就是一样的。

---

## 8. 常见坑

- 登录二维码过期：重开 WebUI 刷新
- AstrBot 显示适配器离线：多半是 6199 端口被占，或反向 WS 地址写错（要带 `/ws`）
- 消息发不出：检查小鲸那个号是否被风控、以及 AstrBot 里平台适配器是否 Online
