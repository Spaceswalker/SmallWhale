# 提交说明怎么写

本仓库的提交说明固定成 `<type>: <一句话>` 的形式。模板文件是仓库根目录的 `.gitmessage`。

## 可用的 type

| type | 什么时候用 |
| --- | --- |
| `feat` | 新增功能、新文件 |
| `fix` | 修 bug、修机器上真出现过的毛病 |
| `docs` | 只改文档：README、`docs/`、注释 |
| `style` | 只改格式，不改行为：空格、缩进、重命名 |
| `refactor` | 改结构但不改行为 |
| `chore` | 杂项：依赖、脚本、配置 |

## 例子

```
feat: 主动消息加上「没话题就不发」的闸
fix: 修 .gitignore 把 astrbot/ 一起忽略的问题
docs: 补 NapCat 反向 WS 的排错步骤
```

## 两个用法

**1. 直接写一行（最常用）**

```powershell
git add .
git commit -m "fix: 修开始菜单图标不显示"
git push
```

**2. 用模板（会自动带上提示）**

仓库已经设了 `commit.template = .gitmessage`，所以直接 `git commit`（不带 `-m`）会打开编辑器，里面就是模板：把 type 那句话写在第一行，其余注释行删不删都行（`#` 开头的会被忽略）。

## 用脚本帮你检查格式

```powershell
.\scripts\commit.ps1 fix "修开始菜单图标不显示"
```

它会：

1. `git add -A`
2. 检查 type 是不是上面六种之一
3. 拼成 `fix: 修开始菜单图标不显示` 再提交
4. 打印提交结果，提醒你 `git push`

type 写错会直接拒绝，并列出可用的六种。

## 规则

1. 第一行不超过 60 个字，句尾不加句号
2. 一件事一个提交，别把三件不相干的事塞进一条
3. 需要解释的写在空行之后（为什么改、影响什么、怎么验证）
