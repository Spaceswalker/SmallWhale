# 架构

## 一张图

```
        QQ 用户
          │  消息
          ▼
   ┌──────────────┐   反向 WS :6199   ┌──────────────────┐
   │   NapCat     │ ────────────────► │     AstrBot      │
   │ (QQNT 协议)   │                   │  WebUI :6185     │
   └──────────────┘                   └────────┬─────────┘
                                               │ 插件
                                     ┌─────────▼─────────┐
                                     │ astrbot_plugin_    │
                                     │ memories（记忆/   │
                                     │ 日记/主动/过滤）   │
                                     └─────────┬─────────┘
```

> 想让她有张脸（Live2D 桌宠）不在本仓库范围内；模型可以去用 B 站 @神宫凉子 开源的那只，仓库里没有相关代码。

## 各层职责

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| NapCat | QQ 协议、收发消息、登录态 | 说话、记忆 |
| AstrBot | 调模型、上下文、人格、插件调度 | QQ 协议细节、渲染 |
| 记忆插件 | 记什么、何时想起、主动开口、口癖过滤、写日记 | 生成主对话 |

## 一条回复的旅程

1. 主用户在 QQ 说话 → NapCat → AstrBot 的 `on_llm_request` 触发记忆插件
2. 插件挑记忆：纪念日 → 说话人自己的 → 提到的人 → 关键词/语义 → 昨天/最近日记
3. 注入进本轮上下文（附件层 + 必要时抬进 system prompt）
4. 模型回话 → `on_llm_response` 过语言过滤（口癖/regex 剃句）
5. 发回 QQ
7. 日记：每天 00:00 把当天真实对话写成一篇第一人称日记（只写当天、覆盖整天、500 字左右）

## 为什么这么切

- **QQ 协议交给 NapCat**：自己实现协议是常年维护地狱
- **记忆在插件里**：换模型不用动记忆，记忆出问题也不用动模型
- **桌宠独立进程**：崩溃不影响聊天；关掉桌宠照样能聊
- **过滤放在回复链路末端**：模型怎么说改不动，但**发出去之前**能拦
